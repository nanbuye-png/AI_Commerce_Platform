## 一、下单流程

### 1.1 完整时序

```
用户                     Frontend                  Backend                   Inventory           Database
 │                          │                         │                         │                    │
 │  1. 点击"立即购买"        │                         │                         │                    │
 │─────────────────────────>│                         │                         │                    │
 │                          │  2. POST /api/v1/orders │                         │                    │
 │                          │  {items, addressId}      │                         │                    │
 │                          │─────────────────────────>│                         │                    │
 │                          │                         │  3. 校验商品状态         │                    │
 │                          │                         │  (ON_SHELF)             │──────────────────>│
 │                          │                         │                         │                    │
 │                          │                         │  4. 查询库存             │                    │
 │                          │                         │  GET available_stock    │                    │
 │                          │                         │─────────────────────────>│                   │
 │                          │                         │<─────────────────────────│                   │
 │                          │                         │                         │                    │
 │                          │                         │  5. 库存预占             │                    │
 │                          │                         │  校验: available_stock   │                    │
 │                          │                         │       >= 购买数量        │                    │
 │                          │                         │  BEGIN 事务              │                    │
 │                          │                         │  UPDATE inventory        │                    │
 │                          │                         │  SET locked_stock += qty │                    │
 │                          │                         │  WHERE version = ?       │                    │
 │                          │                         │─────────────────────────>│                   │
 │                          │                         │                         │  [行锁]            │
 │                          │                         │                         │                    │
 │                          │                         │  6. 生成订单             │                    │
 │                          │                         │  INSERT order_info       │                    │
 │                          │                         │  status = PENDING_PAYMENT│──────────────────>│
 │                          │                         │  INSERT order_item[]     │                    │
 │                          │                         │  INSERT inventory_record │                    │
 │                          │                         │  COMMIT 事务             │                    │
 │                          │                         │─────────────────────────>│                   │
 │                          │                         │                         │                    │
 │                          │  7. 返回订单信息         │                         │                    │
 │                          │<─────────────────────────│                         │                    │
 │  8. 展示订单确认页        │                         │                         │                    │
 │<─────────────────────────│                         │                         │                    │
```

### 1.2 下单校验规则

| 校验项 | 校验时机 | 校验失败处理 |
|--------|----------|--------------|
| 商品是否存在 | 步骤 3 | 返回 404（30001: 商品不存在） |
| 商品是否上架 | 步骤 3 | 返回 400（30002: 商品已下架） |
| SKU 是否存在 | 步骤 4 | 返回 404 |
| 库存是否充足 | 步骤 5 | 返回 400（30003: 库存不足） |
| 收货地址是否存在 | 步骤 3 | 返回 400 |
| 用户是否登录 | 步骤 2（Gateway 层） | 返回 401 |

### 1.3 库存预占（关键）

```
下单时库存变更:
  ┌─────────────────────────────────────┐
  │                                     │
  │  available_stock  ─────保持不变───── │  (下单不扣 available，仅锁定)
  │  ↓                                  │
  │  locked_stock     ───── +qty ────── │  (预占库存，防超卖)
  │                                     │
  └─────────────────────────────────────┘

为什么下单时只锁不扣？
  - 用户可能30分钟内放弃支付 → 释放锁
  - 用户可能取消订单 → 释放锁
  - 只有支付成功才真正扣减 available_stock
```

### 2.2 支付幂等设计

**transaction_id UNIQUE 约束:**

```sql
-- payment 表
ALTER TABLE payment ADD UNIQUE INDEX uk_transaction_id (transaction_id);
```

**回调幂等处理流程:**

```
收到支付回调
      │
      ▼
┌─────────────────┐
│ 1. 验证回调签名   │  → 验签失败: 丢弃/告警
└────────┬────────┘
         │ 签名通过
         ▼
┌─────────────────┐
│ 2. 提取           │
│   transaction_id │
│   out_trade_no   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. 查询           │
│   transaction_id │
│   是否已存在      │
└────┬───────┬────┘
     │       │
  已存在    不存在
     │       │
     ▼       ▼
┌──────┐ ┌──────────────────┐
│ 直接  │ │ 4. 更新 Payment   │
│ 返回  │ │    status=SUCCESS │
│ 200  │ │    transaction_id  │
└──────┘ │    payment_time   │
         │                   │
         │ 5. 更新 Order      │
         │    status=PAID    │
         │                   │
         │ 6. 库存扣减        │
         │    available -= qty│
         │    locked -= qty  │
         │                   │
         │ 7. 返回 200        │
         └──────────────────┘
```

### 2.3 支付超时处理

- 订单创建后 **30 分钟** 内未支付 → 自动取消
- 定时任务扫描 `status = PENDING_PAYMENT AND created_time < NOW() - 30min`
- 取消流程: Update order.status → CANCELLED → Release inventory.locked_stock

## 三、库存生命周期

### 3.1 库存状态变化总览

```
┌──────────────────────────────────────────────────────────────────┐
│                       库存生命周期                                │
│                                                                  │
│   ┌────────────┐                                                 │
│   │ 商家设置初始 │                                                 │
│   │  库存数量   │                                                 │
│   └─────┬──────┘                                                 │
│         │                                                        │
│         ▼                                                        │
│   ┌──────────────────┐                                           │
│   │ available_stock  │  ← 可售库存                               │
│   │   = 100          │                                           │
│   │ locked_stock = 0 │                                           │
│   └────────┬─────────┘                                           │
│            │                                                     │
│     ┌──────┼──────────┬──────────────┐                           │
│     │      │          │              │                           │
│     ▼      ▼          ▼              ▼                           │
│   下单   活动预留    退货入库        补货                           │
│     │      │          │              │                           │
│     ▼      ▼          ▼              ▼                           │
│  locked  reserved  available       available                     │
│  += qty  += qty    += qty          += qty                        │
│     │                                                           │
│     │  支付成功                                                   │
│     ▼                                                           │
│  available -= qty                                                │
│  locked    -= qty                                                │
│     │                                                           │
│     │  订单取消/超时                                              │
│     ▼                                                           │
│  locked -= qty  (释放预占)                                       │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 关键库存操作

| 操作 | 触发时机 | available_stock | locked_stock | reserved_stock | InventoryRecord |
|------|----------|:---:|:---:|:---:|:---:|
| 创建订单 | 用户提交订单 | — | +购买数量 | — | ✅ SALE_LOCK |
| 支付成功 | 支付回调 | -购买数量 | -购买数量 | — | ✅ SALE_CONFIRM |
| 订单取消 | 用户/超时取消 | — | -购买数量 | — | ✅ RELEASE |
| 退款完成 | 退款回调 | +退款数量 | — | — | ✅ RETURN |
| 商家补货 | 商家后台操作 | +补货数量 | — | — | ✅ INBOUND |
| 活动预留 | 活动创建 | — | — | +预留数量 | ✅ RESERVE |
| 释放预留 | 活动结束/取消 | — | — | -预留数量 | ✅ UNRESERVE |

### 3.3 并发控制

```
下单并发场景（100人同时抢1件商品）:

  请求1                    请求2                    请求3
   │                        │                        │
   ▼                        ▼                        ▼
  BEGIN TXN               BEGIN TXN               BEGIN TXN
   │                        │                        │
   ▼                        ▼                        ▼
  SELECT * FROM             SELECT * FROM             SELECT * FROM
  inventory                 inventory                 inventory
  WHERE sku_id=1            WHERE sku_id=1            WHERE sku_id=1
  FOR UPDATE                FOR UPDATE                FOR UPDATE
   │                        │                        │
   │  (行锁，等待)            │  (行锁，等待)            │
   ▼                        │                        │
  available=1               │                        │
  校验通过                   │                        │
  locked += 1               │                        │
  INSERT order              │                        │
  COMMIT                    │                        │
   │                        ▼                        │
   │                  (获得锁)                        │
   │                  available=0                     │
   │                  校验失败!                        │
   │                  返回 "库存不足"                   │
   │                  ROLLBACK                        │
   │                                                  │
   │                                                  ▼
   │                                            (获得锁)
   │                                            available=0
   │                                            校验失败!
   │                                            返回 "库存不足"
   │                                            ROLLBACK

  结果: 仅请求1成功，请求2和3收到明确的"库存不足"错误
```

### 4.2 库存恢复规则

| 退款类型 | 订单状态 | 库存恢复 | 说明 |
|----------|----------|:---:|------|
| 未发货退款 | PAID / PROCESSING | ✅ 恢复 | 商品未出库，库存直接恢复 |
| 已发货退款 | SHIPPED | ✅ 恢复（退货确认后） | 需用户退货，商家确认收货后恢复库存 |
| 部分退款 | PAID / PROCESSING | ✅ 部分恢复 | 仅恢复退款商品对应的库存 |
| 已完成后退款 | COMPLETED | ✅ 恢复 | 售后流程 |

## 五、订单超时自动取消

### 5.1 超时策略

| 场景 | 超时时间 | 处理 |
|------|----------|------|
| 待支付订单 | 30 分钟 | 自动取消 → 释放库存锁 |
| 已发货 → 自动确认收货 | 7 天 | 自动流转为 COMPLETED |

### 5.2 定时任务设计

```
每 1 分钟执行一次:

1. 扫描超时待支付订单:
   SELECT * FROM order_info
   WHERE status = 'PENDING_PAYMENT'
   AND created_time < NOW() - INTERVAL 30 MINUTE

2. 对每个超时订单:
   BEGIN 事务
   UPDATE order_info SET status = 'CANCELLED', updated_time = NOW()
   WHERE id = ? AND status = 'PENDING_PAYMENT'  -- 乐观锁双重确认

   UPDATE inventory SET locked_stock = locked_stock - order_qty,
                        updated_time = NOW()
   WHERE sku_id = ?

   INSERT INTO inventory_record (type='RELEASE', ...)
   COMMIT
```
