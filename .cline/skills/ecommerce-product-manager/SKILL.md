## 一、电商产品思维

### 1.1 用户购物生命周期

```
认知 → 兴趣 → 考虑 → 购买 → 使用 → 复购 → 推荐
 │       │       │       │      │      │       │
 └─ 广   └─ 发   └─ 比   └─ 下   └─ 体  └─ 回   └─ 分
    告      现      价      单      验      购      享
```

- **认知阶段**：用户通过搜索、推荐、社交广告首次接触商品
- **兴趣阶段**：商品卡片/列表页促成点击进入详情
- **考虑阶段**：详情页规格、评价、对比驱动决策
- **购买阶段**：购物车 → 结账流程，减少流失
- **使用阶段**：订单跟踪、售后保障建立信任
- **复购阶段**：个性化推荐 + 会员体系驱动回访
- **推荐阶段**：评价体系 + 分享机制形成裂变

### 1.2 用户需求分析

| 需求类型 | 用户提问 | 产品应答 |
|---------|---------|---------|
| 功能性需求 | "我想买一双跑鞋" | 搜索 + 分类 + 筛选 |
| 价格需求 | "哪个性价比最高" | 价格排序 + 折扣标签 + 对比 |
| 品质需求 | "这质量好吗" | 评价 + 评分 + 品牌背书 |
| 适配需求 | "我该穿多大码" | 尺码指南 + AI 推荐 |
| 安全需求 | "退换方便吗" | 退换政策 + 客服入口 |
| 社交需求 | "别人都买什么" | 热销排行 + 购买记录 |
| 即时需求 | "我马上要" | 快速配送 + 库存标识 |

### 1.3 转化漏斗

```
访客 (100%)
  │
  ├─ 首页跳出：-40%
  │
  ▼
浏览商品 (60%)
  │
  ├─ 无兴趣离开：-50%
  │
  ▼
查看详情 (30%)
  │
  ├─ 对比后离开：-40%
  │
  ▼
加入购物车 (18%)
  │
  ├─ 购物车放弃：-60%
  │
  ▼
完成结账 (7.2%)

优化目标：
- 首页→浏览：提升推荐精准度，降低跳出率
- 浏览→详情：优化商品卡片吸引力
- 详情→加购：价格透明 + 信任元素
- 加购→结账：简化流程 + 提醒策略
```

### 1.4 用户体验优化

- **最小阻力路径**：核心转化路径上的每一步都必须简洁明确
- **即时反馈**：用户操作后 300ms 内给予视觉/文字反馈
- **容错设计**：关键操作（如删除地址、提交订单）需二次确认
- **渐进披露**：复杂信息（如规格参数、退换政策）默认折叠，按需展开
- **空状态设计**：无数据时提供可操作的引导（"去逛逛"、"去收藏"）

## 二、商城信息架构

### 2.1 首页设计

**信息区块优先级（从上到下）**：

1. **顶部导航**：Logo + 搜索框 + 购物车 + 个人中心
2. **Banner 轮播**：主推活动/新品，自动轮播 + 手动切换
3. **分类快捷入口**：8-10 个图标入口（2 行 × 4-5 列）
4. **限时/秒杀区**：倒计时 + 商品缩略图列表
5. **为你推荐**：个性化推荐商品流（瀑布流或双列卡片）
6. **热销排行**：按销量/好评率排序的商品列表
7. **品牌专区**：横向滚动的品牌 Logo 列表
8. **底部导航**：首页、搜索、购物车、个人中心

**设计原则**：
- 首屏内容（Hero Area）必须传达平台核心价值
- 推荐内容随着用户行为数据积累逐步个性化
- 每个区块不超过 6-8 个商品展示位
- 区块之间使用 16px-24px 留白分隔

### 2.2 商品分类设计

**分类层级**：

```
一级分类（8-12个）
  ├── 二级分类（每个一级下 3-8 个）
  │     ├── 三级分类（可选）
  │     └── 品牌筛选
  └── 属性筛选（价格、颜色、尺寸、材质）
```

**分类导航形式**：
- **移动端**：侧边抽屉式（左滑出现），一级分类垂直列表，点击展开二级
- **桌面端**：顶部导航悬停下拉，平铺展示二三级分类

**分类页信息**：
- 当前分类路径面包屑
- 子分类入口（图标 + 名称）
- 排序选项（综合 / 销量 / 价格 / 新品）
- 筛选面板（品牌 / 价格区间 / 属性）
- 商品网格列表

### 2.3 搜索体验

**搜索流程**：

```
输入关键词
  ├── 即时联想（>= 2 字符，300ms 防抖）
  │     ├── 历史搜索（最近 10 条）
  │     ├── 热门搜索词
  │     └── 联想补全 + 结果数量预估
  │
  └── 搜索无结果
        ├── 拼写建议（"您是不是想找：XXX"）
        ├── 热门搜索推荐
        └── 分类浏览入口

搜索结果页
  ├── 结果统计（"找到 XX 件商品"）
  ├── 排序 + 筛选
  ├── 商品列表（支持列表/网格切换）
  └── 分页 / 无限滚动
```

**搜索排序策略**：
- **综合**：权重 = 相关性 × 销量 × 评分 × 时效
- **销量**：按近 30 天销量降序
- **价格**：按价格升降序
- **新品**：按上架时间降序
- **好评**：按评分降序

### 2.4 商品详情页设计

参见 `ai-commerce-ui-designer` Skill 第三章 3.2 节。

补充产品层面策略：
- **稀缺性提示**：低库存、限时折扣、多人正在浏览
- **社交证明**：已购人数、实时购买动态
- **风险消除**：免费退换、正品保障、质保说明
- **向上销售**：升级款、配件推荐、组合套餐
- **交叉销售**：浏览此商品的用户还看了

### 2.5 购物车设计

**购物车功能清单**：

```
□ 商品列表（缩略图 + 名称 + 规格 + 单价 + 数量 + 小计）
□ 数量调整（+/- 按钮，支持输入）
□ 选中/取消选中（全选 + 单选）
□ 商品失效提示（下架、库存不足标灰）
□ 优惠提示（满减、满赠、优惠券入口）
□ 预估总计（商品金额 + 运费 + 优惠抵扣）
□ 去结算按钮（固定底部，显示选中商品数）
□ 收藏移入（商品移至收藏夹）
□ 删除商品（二次确认）
□ 凑单推荐（未达包邮/满减门槛时展示）
```

**购物车放弃挽回策略**：
- 离开页面时弹窗提示
- 未登录用户的购物车保存在 localStorage
- 登录用户购物车持久化到服务端
- 定时推送购物车提醒（24h/48h/72h）

### 2.6 订单流程设计

```
购物车 → 确认订单 → 支付 → 支付成功 → 订单详情
                │
                ├─ 选择收货地址（新增/编辑/选择）
                ├─ 选择配送方式（标准/加急）
                ├─ 选择支付方式（微信/支付宝/银行卡）
                ├─ 优惠券/积分抵扣
                ├─ 买家留言
                └─ 订单总览（商品清单 + 金额明细）

订单状态机：
待付款 → 待发货 → 待收货 → 已完成
  │         │         │        │
  ├─ 取消    ├─ 发货   ├─ 确认   ├─ 评价
  └─ 过期    └─ 退款   └─ 退货   └─ 售后
```

## 三、商品展示逻辑

### 3.1 商品卡片设计原则

**信息层级**（重要性从上到下）：

1. **商品图片**：1:1 方形主图，清晰展示商品主体
2. **商品标题**：限 2 行，包含品牌名 + 商品名 + 关键属性
3. **价格信息**：当前价（粗体）+ 原价（划线）+ 折扣标签
4. **评分/销量**：星级评分 + 评价数 / 月销量
5. **规格标识**：颜色点 / 规格标签 / 新品标 / 热销标
6. **操作按钮**：加入购物车 / 收藏 / Quick Add

**卡片变体**：
- **竖版卡片**（默认）：图片在上，文字在下
- **横版卡片**（搜索/收藏夹）：图片在左，文字在右
- **紧凑卡片**（推荐区域/关联商品）：小图 + 精简信息

### 3.2 商品排序逻辑

| 排序方式 | 适用场景 | 排序依据 |
|---------|---------|---------|
| 综合排序 | 默认、搜索、分类页 | 算法加权（相关性+热度+转化率） |
| 销量排序 | 比价、热门商品 | 近 30 天销量降序 |
| 价格排序 | 预算导向用户 | 价格字段升/降序 |
| 新品排序 | 追求新款用户 | 上架时间降序 |
| 好评排序 | 品质导向用户 | 综合评分降序 |
| 收藏排序 | 用户收藏夹 | 收藏时间降序 |

### 3.3 推荐展示逻辑

**推荐场景矩阵**：

| 场景 | 推荐算法 | 展示位 | 目标 |
|------|---------|--------|------|
| 首页为你推荐 | 协同过滤 + 用户画像 | 首页信息流 | 提升点击率 |
| 商品详情相关 | 物品协同过滤（Item-CF） | 详情页底部 | 提升交叉销售 |
| 购物车推荐 | 关联规则（Market Basket） | 购物车底部 | 提升客单价 |
| 搜索后推荐 | 内容匹配 + 热销 | 搜索结果页尾 | 提升转化率 |
| 订单完成推荐 | 用户画像 + 潮流趋势 | 支付成功页 | 提升复购率 |
| 搭配推荐 | 款式/品类搭配算法 | 详情页/搭配页 | 提升连带率 |

**推荐展示规范**：
- 每次展示 6-12 个商品
- 支持「换一批」刷新
- 推荐理由标注（"浏览过"、"相似商品"、"热销"）
- 用户反馈机制（"不感兴趣"）

### 3.4 价格展示策略

| 价格类型 | 展示方式 | 示例 |
|---------|---------|------|
| 标准价 | 当前价粗体 + 元/¥符号 | **¥299.00** |
| 折扣价 | 当前价 + 原价划线 + 折扣百分比 | **¥199.00** ~~¥399.00~~ -50% |
| 区间价 | 最低价-最高价 | ¥199.00 - ¥599.00 |
| 起售价 | 最低价 + "起" | ¥199.00 起 |
| 会员价 | 当前价 + 会员标签 | **¥179.00** 👑 会员价 |
| 分期价 | 每期价格 + 期数标识 | ¥29.90 × 12 期 |
| 套装价 | 套装价 + 单品总价对比 | **¥499.00** 套装 省 ¥100 |

**价格心理学原则**：
- 整数定价（¥299 → ¥299 而非 ¥298.99）
- 促销价使用鲜艳色调（红色/橙色）
- 对比价（原价与现价）强化优惠感知
- 分期展示降低高价商品的心理门槛

### 3.5 信任元素设计

```
商品详情页信任元素（按展示顺序）：

1. 顶部保障条
   [30天退换] [正品保障] [极速发货] [全国包邮]

2. 评价区
   ★★★★☆ 4.8 (1234条评价)
   └─ 图文评价（默认展示 3 条最有帮助的评价）
   └─ "查看全部评价" 链接

3. 购买动态
   "张三 3 分钟前购买了此商品"
   "商品已被浏览 2345 次"

4. 品牌背书
   [品牌故事] [品牌资质] [合作品牌Logo]

5. 售后保障
   └─ 退换政策详细说明
   └─ 质保期限说明
   └─ 客服联系方式
```

## 四、营销体系

### 4.1 活动页面设计

**活动类型**：

| 活动类型 | 目的 | 设计重点 |
|---------|------|---------|
| 限时秒杀 | 制造紧迫感，提升转化 | 倒计时、进度条、库存指示 |
| 满减满赠 | 提升客单价 | 进度条可视化 + 凑单推荐 |
| 新人专享 | 拉新转化 | 首单优惠标识 + 引导注册 |
| 节日大促 | 集中爆发销量 | 主题视觉 + 氛围渲染 |
| 品牌日 | 品牌曝光 + 销售 | 品牌视觉 + 专属优惠 |
| 拼团 | 社交裂变 | 进度提示 + 分享引导 |

**活动页面结构**：
```
活动 Banner（全宽视觉）
  ├── 活动规则简短说明
  ├── 倒计时（持续活动）
  ├── 商品列表（活动价标识）
  ├── 优惠券领取区
  ├── 阶梯优惠进度条
  └── 活动说明折叠区
```

### 4.2 优惠券

**优惠券类型**：
- **满减券**：满 X 减 Y（如满 299 减 50）
- **折扣券**：X 折优惠（如 8 折，最高减 Y）
- **现金券**：无门槛立减 Y 元
- **运费券**：免运费
- **品类券**：指定品类可用
- **新人券**：新注册用户专享

**优惠券展示规范**：
- 可用优惠券在购物车/结算页高亮展示
- 不可用优惠券置灰并标注原因
- 推荐最优优惠组合（系统自动选择最优惠方案）
- 过期提醒（到期前 24h 推送）

### 4.3 促销策略

**促销手段矩阵**：

| 手段 | 触达时机 | 目标 |
|------|---------|------|
| 限时折扣 | 商品详情页 | 加速购买决策 |
| 满减阶梯 | 购物车 | 提升客单价 |
| 多件折扣 | 商品详情/加购 | 提升件单价 |
| 首单优惠 | 首页/注册后 | 拉新转化 |
| 会员专享价 | 会员中心/商品页 | 会员黏性 |
| 积分抵扣 | 结算页 | 积分体系活跃 |
| 加价购 | 购物车/结算页 | 清库存/推新品 |
| 赠品促销 | 商品详情/购物车 | 提升购物体验 |

**促销规则设计原则**：
- 规则简单明了，用户 5 秒内可理解
- 优惠叠加规则清晰（如：满减与优惠券不可叠加）
- 促销价格需标注有效期
- 避免过度促销损害品牌价值

### 4.4 推荐购买

**推荐购买场景**：

1. **商品详情页 — 搭配推荐**
   - "经常一起购买"（基于关联规则）
   - "完成这套搭配"（基于款式搭配）
   - 展示组合价 + 一键加购

2. **购物车 — 加购推荐**
   - "再加 XX 元可享受满减"
   - "买了 XX 的用户也买了"
   - 底部横向滚动推荐卡片

3. **订单完成 — 再次推荐**
   - "猜你喜欢"
   - "购买此商品的用户还买了"
   - 提供复购快捷入口

### 4.5 复购设计

**复购驱动机制**：

```
用户分层 → 触发策略 → 触达方式 → 循环优化
  │           │           │           │
  ├─ 新客     ├─ 复购券   ├─ Push     ├─ A/B 测试
  ├─ 活跃     ├─ 积分加倍 ├─ 短信     ├─ 数据监控
  ├─ 沉睡     ├─ 专属活动 ├─ 站内信   └─ 策略调整
  └─ 流失     └─ 召回优惠 └─ 邮件
```

**用户分层复购策略**：
- **新客（首单后 7 天）**：发放复购优惠券，推荐关联商品
- **活跃用户（月购 ≥ 2 次）**：会员积分加倍，专属新品预览
- **沉睡用户（30 天未访问）**：Push/短信召回，推送感兴趣商品
- **流失用户（90 天未下单）**：大额召回优惠 + 问券调查原因

## 五、AI Commerce 场景设计

### 5.1 AI Commerce 核心原则

> **AI 不是替代商城，而是增强商城。**

- AI 功能作为增值体验，不阻塞核心购物流程
- AI 推荐需要可解释（提供推荐理由）
- AI 交互要有温度（自然语言、友好语气）
- AI 功能要有明确的触发入口和可预期的结果
- 用户始终有最终决策权，AI 仅提供建议

### 5.2 AI 智能搜索

**能力定义**：

```
传统搜索             AI 增强搜索
─────────           ────────────
关键词匹配      →    语义理解
文本搜索        →    多模态（文本 + 图片）
固定结果排序    →    个性化排序
无结果=失败     →    意图理解 + 引导
单一搜索结果    →    结果 + 解释 + 追问
```

**AI 搜索交互流程**：

```
用户输入："给女朋友买个生日礼物，预算500以内"
  │
  ▼
AI 理解意图：
  ├─ 对象：女性
  ├─ 场景：生日礼物
  ├─ 预算：≤ 500 元
  └─ 品类：未指定（自动推荐礼品品类）
  │
  ▼
AI 搜索结果展示：
  ├─ "为您找到了 23 件适合送女友的礼物"
  ├─ 推荐理由标签（"人气款"、"好评如潮"、"精致包装"）
  ├─ 追问："她有什么兴趣爱好？我可以再帮您缩小范围"
  └─ 快捷筛选：价格区间 / 品类 / 风格
```

**交互设计要点**：
- 搜索框常驻 AI 图标按钮，点击进入 AI 搜索模式
- AI 搜索对话框支持多轮对话
- 搜索结果以标准商品卡片展示
- 支持 AI 追问细化需求
- 可随时切换回传统搜索

### 5.3 AI 商品推荐

**推荐类型**：

| 推荐类型 | 算法 | 展示位置 | 推荐理由文案 |
|---------|------|---------|------------|
| 个性化推荐 | 协同过滤 + 用户画像 | 首页"为你推荐" | "根据您的浏览记录" |
| 关联推荐 | 物品协同过滤 | 详情页"相似商品" | "与 XX 商品相似" |
| 热门推荐 | 实时热度计算 | 首页"热销榜单" | "本周热销 Top 10" |
| 搭配推荐 | 搭配规则/图神经网络 | 详情/搭配页 | "完成这套搭配" |
| 新品推荐 | 时间加权 | 首页"新品上市" | "刚刚上架" |
| 场景推荐 | 场景标签 | 搜索/活动页 | "适合 XX 场景" |

**AI 推荐展示设计**：
- 推荐卡片底部折叠展示推荐理由
- 提供「为什么推荐这个」展开按钮
- 用户可点击「不感兴趣」反馈
- "换一批"按钮刷新推荐内容
- 推荐结果数控制：移动端 ≤ 6，桌面端 ≤ 12

### 5.4 AI 购买顾问

**使用场景**：

```
用户："我想买一台笔记本，平时办公和偶尔玩游戏"
  │
  ▼
AI 顾问多轮对话：
  1. "您对品牌有偏好吗？（如联想、华为、苹果）"
  2. "预算大概在什么范围？（如 5000-8000 元）"
  3. "有什么特别需求吗？（如轻薄便携、长续航）"
  │
  ▼
AI 输出推荐方案：
  ├─ 推荐 Top 3 商品卡片
  ├─ 对比表（CPU/内存/显卡/重量/价格）
  ├─ 选购建议文字
  └─ "是否要加入购物车？" 快捷按钮
```

**设计规范**：
- 购买顾问入口：商品详情页、搜索页、首页
- 对话界面使用气泡布局
- AI 回复使用打字机效果
- 快捷操作按钮展示在回复下方
- 支持对话记录回溯

### 5.5 AI 搭配推荐

**能力定义**：

- **单品搭配**：根据选中的商品推荐搭配商品（如上衣+下装、手机+手机壳）
- **套装搭配**：推荐完整搭配方案（如全身穿搭、全套数码装备）
- **场景搭配**：根据场景推荐组合（如旅行必备、办公套装）

**搭配展示设计**：

```
搭配方案入口
  ├── "AI 搭配" 按钮（商品详情页底部）
  │
  ▼
搭配方案页
  ├── 方案标题（"通勤休闲风"、"户外运动风"）
  ├── 搭配商品列表（横向滚动）
  │     ├─ 主商品（已选中）
  │     ├─ 搭配商品 1（推荐）
  │     ├─ 搭配商品 2（推荐）
  │     └─ 搭配商品 3（推荐）
  ├── 组合总价
  ├── "一键加购" 按钮
  └── "换一套" 按钮
```

### 5.6 AI 客服

**能力定义**：

```
AI 客服处理范围：
  ├── 售前咨询（商品信息、规格、库存、物流）
  ├── 售中服务（订单状态、支付问题、地址修改）
  └── 售后服务（退换货申请、退款进度、投诉建议）

AI 客服升级路径：
  AI 客服 → 人工客服（AI 无法解决时）→ 专人跟进
```

**AI 客服界面设计**：
- 浮动气泡按钮（页面右下角）
- 对话窗口可拖拽、可最小化
- 自动问候 + 常见问题快捷按钮
- 支持发送商品链接
- 支持发送截图/图片
- 对话结束后邀请评价

### 5.7 AI 购物助手

**能力定义**：

```
AI 购物助手贯穿全购物流程的能力：

├── 浏览阶段
│     ├─ "根据你的风格推荐"
│     ├─ "今天有什么值得买的？"
│     └─ "预算 XX 元有什么推荐？"

├── 决策阶段
│     ├─ "A 和 B 哪个更好？"
│     ├─ "这款有什么优缺点？"
│     └─ "大家都在买什么？"

├── 购买阶段
│     ├─ "有优惠券吗？"
│     ├─ "什么时候到货？"
│     └─ "怎么用更省钱？"

└── 售后阶段
      ├─ "我的订单到哪了？"
      ├─ "怎么退货？"
      └─ "能开发票吗？"
```

**设计原则**：
- 助手入口全局可用（底部导航 / 浮动按钮）
- 助手具备上下文记忆（同一会话内）
- 助手提供即时答案 + 操作入口
- 助手可以主动推荐（不频繁，每日 ≤ 3 次主动触达）

## 六、产品决策原则

### 6.1 优先用户体验

```
决策优先级：
1. 用户体验（功能对用户是否友好、直观？）
2. 商业价值（功能是否带来收入/转化？）
3. 技术可行性（实现成本是否合理？）
4. 运营效率（是否减轻运营负担？）

当冲突时：
  ├─ 用户体验与商业价值冲突 → 优先用户体验
  ├─ 用户体验与技术成本冲突 → 寻找折中方案
  └─ 功能数量与体验质量冲突 → 做少做精
```

### 6.2 优先商业价值

- **高价值 > 低价值**：优先开发核心转化路径上的功能
- **通用需求 > 小众需求**：80% 用户受益的功能优先
- **可衡量 > 不可衡量**：能追踪指标效果的功能优先
- **快速验证 > 完美方案**：MVP 验证后迭代优化

### 6.3 避免功能堆叠

```
功能决策检查清单：

□ 这个功能解决什么用户问题？
□ 有多少用户会遇到这个问题？
□ 这个问题目前有没有替代方案？
□ 这个功能对核心转化指标的影响？
□ 如果不做这个功能，用户会不会流失？
□ 这个功能会增加多少使用复杂度？
□ 上线后如何衡量效果？

原则：
  - 每个新功能必须回答"为什么是现在"
  - 每增加一个功能，考虑能否先移除一个旧功能
  - "少即是多" — 功能越少，体验越好
```

### 6.4 数据驱动优化

**指标体系**：

```
核心电商指标：

├── 流量指标
│     ├─ UV / PV
│     ├─ 新用户占比
│     └─ 来源渠道分布

├── 转化指标
│     ├─ 首页→详情转化率
│     ├─ 详情→加购率
│     ├─ 加购→结账率
│     └─ 整体下单转化率

├── 营收指标
│     ├─ GMV（成交总额）
│     ├─ 客单价
│     ├─ 件单价
│     └─ 复购率

├── 商品指标
│     ├─ 动销率（有销售商品数/总商品数）
│     ├─ 库存周转天数
│     ├─ 缺货率
│     └─ 退货率

└── 体验指标
      ├─ 页面加载时间
      ├─ 搜索成功率
      ├─ 页面跳出率
      └─ NPS（净推荐值）
```

**优化流程**：

```
数据监控 → 发现异常 → 假设原因 → 设计方案 → A/B 测试 → 验证上线 → 持续监控
    │                                                                       │
    └───────────────────────────────────────────────────────────────────────┘
```

## 附录：产品设计速查清单

### 新功能上线路检

- [ ] 是否解决真实的用户需求？
- [ ] 是否对核心转化指标有正向影响？
- [ ] 是否增加用户理解成本？（3 秒内能否理解用途）
- [ ] 是否与现有功能形成冲突或重复？
- [ ] 是否有明确的数据衡量标准？
- [ ] 是否有 A/B 测试方案？
- [ ] 是否有兜底/回退方案？

### 页面设计评审清单

- [ ] 首屏是否传达核心价值？
- [ ] 用户是否知道下一步该做什么？
- [ ] 信息层级是否清晰？
- [ ] 关键操作是否在拇指热区？
- [ ] 空状态/错误状态是否有引导？
- [ ] 加载状态是否有反馈？
- [ ] 是否满足无障碍基本要求？

### AI 功能评审清单

- [ ] AI 功能是否以增值方式呈现？
- [ ] 用户是否明确知道这是 AI 提供的结果？
- [ ] AI 推荐是否有解释/理由？
- [ ] 用户是否有否决/不感兴趣的权力？
- [ ] 是否有标准回退方案（AI 不可用时）？
- [ ] AI 交互是否自然、友好？
